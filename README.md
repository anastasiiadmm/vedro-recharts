# 🏔️ Alps MeteoGIS Studio

Интерактивное аналитическое веб-приложение для мониторинга и визуализации пространственно-временных метеорологических и климатических данных Альпийского региона.

Проект построен на стеке: **React 18**, **TypeScript**, **Vedro** (State Management), **MapLibre GL JS** (Interactive GIS WebGL Engine) и **Recharts** (Data Visualization & Time-Series Analytics).

---

## 🚀 Руководство по запуску

### 1. Системные требования
- **Node.js**: версия `18.0.0` или выше (проверить: `node -v`)
- **npm**: версия `9.0.0` или выше (проверить: `npm -v`)
- Поддерживаемые браузеры: Chrome, Firefox, Safari, Edge (с поддержкой WebGL)

## 🏛️ Архитектура приложения

Приложение спроектировано по принципу **модульного разделения ответственности (Separation of Concerns)** с однонаправленным и детерминированным потоком данных:

```
                      ┌───────────────────────────────────────────────┐
                      │              User Interaction                 │
                      │  (Timeline scrub, Recharts click, Map pin)    │
                      └───────────────────────┬───────────────────────┘
                                              │
                                              ▼
                      ┌───────────────────────────────────────────────┐
                      │              Vedro Store & Actions            │
                      │   - currentTimeIndex      - activeLayerIds    │
                      │   - selectedStationId     - requestId         │
                      └───────────────┬───────────────┬───────────────┘
                                      │               │
                     ┌────────────────┴────────┐      │
                     ▼                         ▼      ▼
        ┌─────────────────────────┐      ┌─────────────────────────┐
        │     GisDataService      │      │     React Components    │
        │  (AbortController,      │      │ (Subscribed via         │
        │   LRU Cache, Async Gen) │      │  useAppSelector)        │
        └────────────┬────────────┘      └────────────┬────────────┘
                     │                                │
                     ▼                                ▼
        ┌─────────────────────────┐      ┌─────────────────────────┐
        │  MapLibre WebGL Layer   │◄─────┤   Recharts Time-Series  │
        │  (Heatmap, Vectors,     │      │   & Interactive Metric  │
        │   Solar Grid, 3D Tower) │      │   KPI Cards             │
        └─────────────────────────┘      └─────────────────────────┘
```

## 🗺️ Выбор картографической библиотеки: Почему MapLibre GL JS?

Для реализации проекта в качестве картографического ядра была выбрана библиотека **MapLibre GL JS**. Ниже приведено подробное обоснование выбора в сравнении с альтернативами:

### Сравнительный анализ альтернатив:
- **Mapbox GL JS**: Начиная с версии 2.0+ перешел на проприетарную лицензию с обязательным указанием платёжных данных, строгой тарификацией за загрузки карты и встроенной телеметрией. **MapLibre GL JS** — полностью открытый (BSD-3-Clause) community-driven форк, не имеющий вендор-лока и лицензионных ограничений.
- **Google Maps JS API**: Ориентирован в первую очередь на адресацию, POI и автомобильную навигацию. Имеет высокий порог стоимости, громоздкий API и слабую оптимизацию под кастомные WebGL-слои метеорологических данных.
- **OpenLayers / Leaflet**: Исторически ориентированы на 2D-рендеринг тайлов через Canvas/DOM. При работе с динамическими сетками из десятков тысяч векторных точек и необходимости честного 3D-наклона камеры (`pitch`/`bearing`) с 3D-экструзиями зданий, производительность OpenLayers/Leaflet значительно уступает нативному WebGL-конвейеру MapLibre.

### Ключевые преимущества MapLibre GL JS в проекте:
1. **Аппаратное WebGL-ускорение (60 FPS)**: Высокая производительность при одновременном рендеринге тепловых полей, векторных потоков ветра и полигональных сеток солнечной радиации.
2. **Богатая встроенная типизация GIS-слоев**:
   - `heatmap`: аппаратная интерполяция температурного градиента на GPU;
   - `circle` / `symbol`: динамические маркеры со свободным вращением по азимуту вектора ветра;
   - `fill`: полигональные сетки инсоляции с поддержкой прозрачности и mouse-событий;
   - `fill-extrusion`: аппаратный 3D-рендеринг метеорологической вышки и зданий на пике Цугшпитце с учетом теней и высоты.
3. **Бесплатный тайловый провайдер без ключей**: В качестве базовой подложки используется темная картографическая тема *Esri World Dark Gray Canvas* с нулевой зависимостью от платных API-ключей.

## 📦 Управление состоянием в Vedro

Состояние приложения полностью централизовано в **Vedro store** (`createVedro<AppState>`):

- **Атомарные селекторы**: хук `useAppSelector` подписывает компоненты только на те поля состояния, которые им действительно нужны. Например, изменение положения ползунка прозрачности слоя обновляет только `MapContainer` и `LayerManager`, не вызывая ререндера графиков `TimeSeriesChart`.
- **Единый источник истины (Single Source of Truth)**: такие параметры, как `currentTimeIndex`, `selectedStationId`, `activeLayerIds` и `mapViewState`, синхронно потребляются всеми независимыми модулями.
- **Диспетчеризация**: все модификации выполняются через типизированные методы `AppStoreActions`.

## 🔄 Связь: Timeline ↔ Vedro State ↔ Карта ↔ Recharts

В приложении реализован **бесшовный двусторонний поток данных**:

1. **Timeline → Store → Map & Recharts**:
   - Пользователь перемещает ползунок времени или нажимает «Play» (или клавишу `Space`);
   - Срабатывает `AppStoreActions.setTimeIndex(index)`;
   - `Vedro` обновляет `currentTimeIndex`;
   - На карте плавно обновляются GeoJSON-источники слоев (температура, векторное поле ветра, сетка солнечной радиации) и значения на маркерах станций;
   - На графике Recharts вертикальная линия `ReferenceLine` и маркер `ReferenceDot` мгновенно перемещаются на выбранный час.
2. **Recharts → Store → Map & Timeline (Двусторонняя синхронизация)**:
   - Пользователь кликает на любую точку графика Recharts в окне аналитики;
   - Срабатывает обработчик `onClick` с определением выбранного `activeTooltipIndex`;
   - Store обновляет время, что автоматически синхронизирует Timeline и слои карты.
3. **Map Station Pin → Store → Recharts (Пространственная фильтрация)**:
   - Клик по маркеру метеостанции (например, *Zugspitze Peak Station 2962m* или *Innsbruck 1120m*) на карте переключает аналитический график Recharts с усредненных региональных данных на детальный локальный микроклиматический ряд конкретной станции, а камера карты центрируется на выбранном объекте.

## ⚡ Асинхронность и защита от Race Conditions

При быстром перемещении по Timeline (скраббинге) или переключении скорости воспроизведения возникает проблема **out-of-order ответов** (когда более старый тяжелый запрос завершается позже более нового).

В `gisDataService.ts` и `appStore.ts` реализована многоуровневая защита:

1. **Уникальный инкрементальный Sequence ID (`requestId`)**:
   - При каждом вызове `setTimeIndex` генерируется новый `requestId`.
   - По завершении асинхронной загрузки данных результат проверяется: `latestState.requestId === newRequestId`. Если за время запроса пользователь успел переключить время дальше, устаревший результат отбрасывается.
2. **`AbortController`**:
   - Предыдущие незавершенные сетевые запросы принудительно прерываются сигналом отмены.
3. **In-Memory кэширование**:
   - Загруженные временные срезы кэшируются по составному ключу `${layerId}_${timeIndex}`, что исключает повторные запросы при циклическом воспроизведении и гарантирует отклик за 0 мс.
4. **Симулятор сетевой задержки (Lag Simulator)**:
   - В верхней панели доступен переключатель сетевой задержки (0ms / 150ms / 400ms с джиттером), позволяющий наглядно протестировать поведение системы при высоких задержках и быстром скраббинге.

## 📈 Масштабирование с 3 до 100+ GIS-слоев

В реальной производственной геоинформационной системе архитектура масштабируется следующим образом:

1. **Registry Pattern для слоев**:
   - Описание слоев через единый интерфейс `IGisLayerPlugin` с методами жизненного цикла (`onAdd`, `onUpdate`, `onRemove`, `getLegendConfig`).
2. **Переход от GeoJSON к векторным и растровым тайлам**:
   - Для 100+ слоев данные передаются в виде предгенерированных векторных тайлов **MVT (Mapbox Vector Tiles)** или **PMTiles** / COG (Cloud Optimized GeoTIFF) с пирамидой зумов, загружая только видимый вьюпорт (BBox).
3. **Web Workers & Offscreen Canvas**:
   - Вынос тяжелой интерполяции пространственных данных (кригинг, IDW) и парсинга бинарных форматов (NetCDF, GRIB2) в фоновые Web Workers, сохраняя 60 FPS для UI-потока.
4. **Виртуализация Layer Manager**:
   - Использование `react-virtualized` / `react-window` для списка слоев с группировкой по категориям (Атмосфера, Гидрология, Спутниковые данные, Модели прогнозов).
5. **Deck.gl / WebGL2 Instancing**:
   - Использование Deck.gl слоев (`ParticleLayer`, `H3HexagonLayer`, `TripsLayer`) для миллионных массивов метеорологических частиц.

## 💎 Уникальные и рукописные инженерные компоненты

В отличие от шаблонных типовых решений, в проекте с нуля вручную написаны ключевые математические, графические и картографические модули без использования готовых плагинов:

1. **Рукописный движок анимированных частиц ветра на HTML5 Canvas (`CanvasWindParticleLayer.ts`)**:
   - Анимирует сотни частиц ветра поверх карты через `requestAnimationFrame`;
   - Частицы непрерывно сэмплируют $(u, v)$ компоненты поля скоростей ветра, двигаются по геодезическим координатам, проецируются через `map.project()`, оставляют затухающие шлейфы (trail persistence) и меняют цвет по шкале Бофорта;
   - Автоматически синхронизируется с зумом, вращением камеры и состоянием видимости в Vedro.

2. **Собственный модуль пространственной интерполяции (IDW - Inverse Distance Weighting)** (`src/services/spatialMath.ts`):
   - Реализует формулу Шепарда для расчета непрерывного поля из дискретных точечных наблюдений метеостанций:
     $$Z(x) = \frac{\sum_{i=1}^N w_i(x) z_i}{\sum_{i=1}^N w_i(x)}, \quad w_i(x) = \frac{1}{d(x, x_i)^p + \epsilon}$$

3. **Астрономические уравнения высоты Солнца и фаз сумерек (NOAA Solar Equations)**:
   - Рассчитывает точный угол возвышения солнца $\theta_z$, зенитное расстояние, время истинного солнечного полудня и фазы освещенности (*Daylight*, *Golden Hour*, *Civil Twilight*, *Nautical Twilight*, *Astronomical Twilight*, *Night*);
   - Выводит динамический бейдж астрономической фазы и угол наклона солнца прямо в `Timeline`.

4. **Рукописная полярная диаграмма розы ветров на чистом SVG (`WindRoseChart.tsx`)**:
   - Векторный расчет 8-секторной полярной тригонометрии ($r \cos \theta, r \sin \theta$) для визуализации розы ветров без тяжелых внешних библиотек.

5. **Генератор метеорологических вымпелов ветра по стандарту ВМО (WMO Wind Barbs)**:
   - Создает правильные SVG-флажки (50 узлов - треугольный вымпел, 10 узлов - длинное перо, 5 узлов - короткое полуперо) с правильной ориентацией навстречу ветру.

- **Какие решения были написаны вручную / кастомизированы**:
